## Verification

- Production-domain regressions passed in the final combined frontend run. Coverage includes work-order payloads and guards, scheduling selection/recovery, dispatch refresh, MRP ownership, routing edits and BOM response handling. [validation.md](validation.md) records the final combined totals; targeted runs overlap and are not additive.
- Frontend source/test TypeScript checks and ESLint on owned production components/pages passed with zero lint errors or warnings.
- Chromium exercised mobile Time Clock geometry and New Work Order validation/dirty navigation with synthetic fixtures. The implementation did not perform production writes or a deployment.
- The final approved-scope gap closure passed all Scheduling/WorkOrderDetail regressions: **16 suites / 174 tests**, including four new delay/failure/pending cases. Frontend TypeScript and lint passed after these changes. This is a supplement to the combined run, not an additive coverage total.
- Isolated migration review found one Alembic head, `090_document_revision_chain`, following `089_quote_line_conversion` and `088_api_tokens`. Applying 089/090 to a scratch SQLite schema without their new fields produced zero Alembic model differences for quotes, quote lines and documents; both downgrades succeeded. QuoteLine's foreign-key name also matches migration 089 for metadata-created schemas. This does not claim a PostgreSQL migration rehearsal.
- After the final foreign-key naming alignment, quote conversion and migration regressions passed **17 tests**; Black, isort and model mypy checks passed. The full backend run preceded this metadata-only correction and was not repeated.

## Practical limits

MRP review remains acknowledgement; the planner creates supply documents separately. A Scheduling machine move and its date update remain separate server writes; the UI reports and reconciles partial success. The recorded local Chromium checks cover specific desktop/mobile paths. They are not all-device or assistive-technology conformance, production-write validation, or proof of PostgreSQL lock contention behavior. Staging database/migration validation remains separate from SQLite regression tests.

## Shared navigation and quote review contributions

PartEdit, PartsNew, BOMImportWizard and the new BOM line editor call the shared `markSaved()` after successful writes so deliberate save navigation can proceed while unsaved navigation remains guarded.

The quote review corrected tenant-scoped work-order number generation, nonproduction remaining-line status, stale list/detail associations and refusal to reopen partially converted quotes for line deletion. Quote updates reject stale reviewed timestamps; line-only edits advance the parent timestamp even when totals match. Quote detail eagerly loads work-order links. The expiration editor correction is implemented.

Quote creation also has optional replay protection: a stable UI request key survives ambiguous responses; tenant/request-key uniqueness and a canonical payload hash prevent duplicate keyed creation. Same-payload retries return the saved quote; changed payloads return 409 with the existing quote identity. Legacy keyless callers retain their behavior. Submitted editor fields remain frozen during save.

Permanent quote API and migration tests cover payload equivalence, changed committed payloads, tenant isolation, legacy compatibility and data preservation. These contributions are included in the shared validation record; [quoting-reports.md](quoting-reports.md) describes the complete feature.
