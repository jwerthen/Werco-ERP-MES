## P1 — preserve user intent and truthful outcomes

**PROD-01: Scheduling “Select visible” selects hidden jobs.** [frontend/src/pages/Scheduling.tsx:261–276](https://github.com/jwerthen/Werco-ERP-MES/blob/0a383b8c63926dd02e2a37c5153b43a3b095631b/frontend/src/pages/Scheduling.tsx#L261-L276) filters queueRows by search/work center; line 1402 renders filteredQueueRows. But **788–789** selects unfiltered queueRows. “Select visible” (1280–1281) and header checkbox (1383–1384) call that function; bulk action iterates the full selected list at 688. A filtered machine/part selection can mutate jobs outside the display. Select the displayed collection and disclose retained hidden selections. **Acceptance:** With 12 jobs and 3 matching the filter, both selection controls and the resulting bulk request target exactly 3; changing filters never silently expands scope.

**PROD-02: Removed routed operations return on WO creation.** [frontend/src/pages/WorkOrderNew.tsx:709–711](https://github.com/jwerthen/Werco-ERP-MES/blob/0a383b8c63926dd02e2a37c5153b43a3b095631b/frontend/src/pages/WorkOrderNew.tsx#L709-L711) only filters local rows. **713** detects overrides using individual fromRouting flags, so removal alone does not count. Submit sends `operations: []` at **784–802**. [backend/app/api/endpoints/work_orders.py:2089–2094](https://github.com/jwerthen/Werco-ERP-MES/blob/0a383b8c63926dd02e2a37c5153b43a3b095631b/backend/app/api/endpoints/work_orders.py#L2089-L2094) regenerates routing operations for an empty list. The remove control is exposed at WorkOrderNew 1343–1348. The saved traveler/schedule can disagree with the reviewed form. Track list override separately from row flags and distinguish default routing from explicitly empty operations. **Acceptance:** Delete one routed operation, make no other edits, save: only remaining rows persist. Delete all: validate clearly or honor allowed empty, never silently regenerate.

**PROD-03: MRP “Process”/“Done” does not create supply documents.** [backend/app/api/endpoints/mrp.py:310–340](https://github.com/jwerthen/Werco-ERP-MES/blob/0a383b8c63926dd02e2a37c5153b43a3b095631b/backend/app/api/endpoints/mrp.py#L310-L340) only marks processed and returns `created_reference=None` plus “Create ... manually.” **[frontend/src/pages/MRP.tsx:220–227](https://github.com/jwerthen/Werco-ERP-MES/blob/0a383b8c63926dd02e2a37c5153b43a3b095631b/frontend/src/pages/MRP.tsx#L220-L227)** discards the response. The row says **Process/Done at 137–147**, with no order link or manual-follow-up instruction. A planner can believe supply has been actioned when the PO/WO still needs creation. Use action-specific create-PO/WO flows with prefilled part/quantity/dates and a resulting reference; if acknowledgement only, call it “Mark reviewed” and disclose remaining work. **Acceptance:** “Done” has a defined resolution and document reference or explanation. Prevent repeat pending submissions.

## P2 — reliable context, recovery, daily editing

**PROD-05: WO detail treats failed blocker/material/document reads as empty.** **[frontend/src/pages/WorkOrderDetail.tsx:728–764](https://github.com/jwerthen/Werco-ERP-MES/blob/0a383b8c63926dd02e2a37c5153b43a3b095631b/frontend/src/pages/WorkOrderDetail.tsx#L728-L764)** catches secondary request failures and sets null/empty arrays. **2781,2787–2792** then report 0 open and “This work order has no open issues”; **2350–2354** says no drawing PDF is attached. Material display requires non-null data at **3377**. Promise.all at 747–750 makes a document-picker failure also erase attached documents. Add independent section errors, retained stale data, last-success time and Retry; load independent sources separately. **Acceptance:** Fault-inject each read: no absence claim without successful evidence, and recovery retains context. Scope correction: current WorkOrders, Scheduling, MRP, BOM/Routing lists, and Shop Floor have ErrorState/retry handling; old broad false-empty critique is removed.

**PROD-06: New WO part lookup can overwrite current selection’s preview.** **[frontend/src/pages/WorkOrderNew.tsx:506–605](https://github.com/jwerthen/Werco-ERP-MES/blob/0a383b8c63926dd02e2a37c5153b43a3b095631b/frontend/src/pages/WorkOrderNew.tsx#L506-L605)** makes multiple awaits and updates shared state without request identity/cancellation.
