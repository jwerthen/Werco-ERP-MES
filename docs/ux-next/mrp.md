# MRP recommendations to supply drafts

Implemented in `codex/ux-workflow-improvements`. A planner opens **Review supply draft** from either the latest shortage snapshot or a run's action list. The dialog rechecks current demand and planned supply, then prefills the current shortage quantity, required/due date, preferred supplier and standard cost for a PO, or the released routing/work centers for a WO. Suppliers and work centers display readable names. The planner explicitly creates a draft and opens its linked document to continue the established approval/send or release workflow.

**Mark reviewed remains separate.** It records review status and creates no supply document. Creating a draft does not mark the recommendation reviewed. Run counts and row quantities remain explicitly labeled snapshots. `/mrp?run=<id>&action=<id>` opens the source run and highlights the recommendation, including older runs outside the recent list.

## Implementation and protections

- `GET /mrp/actions/{id}/supply-review` reads current shortage, proposed fields, released routing, available suppliers/work centers, a review fingerprint, and any existing draft. `POST /mrp/actions/{id}/supply-draft` creates the reviewed document, audit records and `MRPSupplyLink` in one transaction.
- Role gates match manual draft creation: admin, manager or supervisor. Tenant predicates protect recommendation, part, supplier, work center and source document lookups. Inactive/deleted parts and suppliers are refused.
- Stale inventory/demand, a newer completed MRP run, changed routing/process-sheet state, excessive quantities and past due dates are refused before creation. A PO uses the existing PO/line schemas and number generator. A WO uses the existing WO/operation schemas, number generator and routing/process-sheet snapshot helper. No route requires an explicit work center and produces one draft operation for subsequent planning.
- One supply link per company/recommendation and one request key per company protect against duplicate drafts. A matching committed replay returns the original document; changed payloads return its recovery link. The dialog retains the exact request and fields after an uncertain transport response. Draft header, lines/operations, source link and audit changes roll back together.
- MRP planning and manual/automatic supply creation share a PostgreSQL advisory transaction lock; each reviewed action also has a row lock. The legacy auto-draft service skips already reviewed/linked actions. Existing legacy result associations remain visible in action responses.
- Remaining firm PO supply and explicitly linked MRP draft PO/WO supply are netted in subsequent MRP runs. Closed PO lines, cancelled/received/closed/deleted POs and completed/deleted WOs do not contribute. Cancelling a draft restores unmet demand on a new run. A partial draft requires another MRP run for the remainder; it does not permit multiple drafts from one historical recommendation.
- Migration `093_mrp_supply_links` follows `092_operational_inbox_state`, with company-scoped uniqueness, one-document CHECK and foreign keys. PostgreSQL enables RLS and revokes the table/sequence from `anon`/`authenticated`, consistent with the application's custom server authentication. Supabase documents that table grants and RLS are separate protections: [Securing your API](https://supabase.com/docs/guides/api/securing-your-api).
- Corrected the pre-existing API/model mismatch: the persisted field is `processed`; `is_processed` is now an ORM alias. Supply result references are resolved from real PO/WO associations instead of accessing a nonexistent model attribute.

- Frontend application/test typechecks and zero-warning ESLint passed for the MRP files. Backend mypy passed for six MRP source modules; Black/isort and Flake8 passed for the modified MRP source/tests.

## Verification limits

This package was tested locally; no production records were changed and no POs were sent or WOs released. These checks do not establish real PostgreSQL contention behavior or all-device browser conformance. The advisory lock coordinates MRP runs and MRP creation paths; it is not a universal inventory reservation lock shared by every inventory mutation. Creation revalidates a current snapshot, while later inventory/order changes require a new MRP run. The existing planning engine nets supply totals across the horizon and does not promise date-phased arrival feasibility. The draft date/routing still requires normal planner review before issuance or release.
