# Saved workspaces and unfinished drafts

Work Orders, Purchasing's active purchase-order list and Quality's NCR/CAR/FAI lists now support named account-owned views. A view contains that table's filters, sort, desktop column order/visibility and row density. Apply changes the relevant filters without replacing record deep links. Update replaces the selected view using its observed version. Save layout remembers presentation for the next visit without changing URL-borne filters. Identity/action columns remain visible; obsolete columns are normalized. Hidden sort columns retain their accessor, and Work Orders' mobile cards use the same ordering.

New work-order, purchase-order and quote forms save private recovery records to the server after an 800 ms debounce, with a Save draft now action. A returning user sees Resume/Remove; loading never silently replaces current typing. Purchasing and Quotes also offer Continue draft on their list. Existing persisted quote editing retains its normal optimistic save workflow. Quote recovery preserves its create request key for ambiguous business-save retries. Work-order recovery preserves the reviewed operation snapshot and rechecks the part's readiness.

Writes serialize and use compare-and-swap versions. Conflicting or ambiguous draft writes pause automatic saving and require reloading the saved copy before a user can choose it. Completing a business save waits for outstanding draft writes before removing their final version. Cleanup failure reports a warning separately from the successful business save. A browser closed during an outstanding save may still lose the latest edit; the existing leave-page warning remains active. These recovery records are not released WOs, issued POs or sent quotes.

Migration 091 adds user_workspace_records. Every API query explicitly includes active company and authenticated user. Module access is rechecked for stored data; Quotes follows its existing authenticated-reader permission contract. Namespace and record-kind allowlists, strict payload fields,200 KB JSON cap,25 records per namespace/kind, and versioned deletion bound and protect the feature. The table enables PostgreSQL RLS and revokes PUBLIC/anon/authenticated access; verified FastAPI sessions use the service database connection. No raw draft payload goes into browser persistent localStorage.

Validation includes backend roundtrip/CAS/delete, other-user/company isolation, permission revocation, read-only sessions, quota, invalid/owner-injected payloads, SQLite migration roundtrip and PostgreSQL migration SQL. Hook regressions cover stale account reads, out-of-order refresh/write, serialization, conflict recovery and completion cleanup. Four real Chromium flows cover saved views and all three draft forms across reloads. Mobile Purchasing and Quality were checked at 390 px and their header layouts corrected to avoid horizontal overflow. PostgreSQL contention has not been exercised locally; SQLite tests do not establish real PostgreSQL lock behavior.
